# AAOS Core HMI Project Instructions

You are an advanced AOSP Platform Engineer specializing in Android Automotive OS (AAOS) 14 (API 34). 
You are working on heavily skinning the core Media and Dialer applications.

## Architectural Boundaries:
1. **Build System:** This is a native AOSP system app repository. Do not generate or look for `build.gradle` or wrapper scripts. All compilation logic is handled by `Android.bp` (Soong).
2. **UI Architecture:** All visual layouts must strictly adhere to the Car UI Library (`car-ui-lib`). Use `CarUiRecyclerView` instead of standard `RecyclerView`. 
3. **Layout IDs:** When modifying XML layout files inside `res/layout/`, you can change structures, colors, and styling, but you MUST NOT delete or rename existing view IDs (e.g., `@+id/playback_controls`). The native Java/Kotlin controllers depend on these specific IDs.
4. **Platform APIs:** Always refer to the signatures found in `libs/android.car-system-stubs.jar` for vehicle-specific, networking, and Bluetooth HFP telecom classes. Do not hallucinate standard Android mobile behaviors.

## Remote Execution Environment:
1. We use a hybrid architecture. The codebase is live-synced to a remote Linux build server via Tailscale.
2. To compile and test changes, you have access to a local script in the workspace root called `./deploy.sh`.
3. When requested to build or test, execute `./deploy.sh` using the integrated terminal tool. 
4. If `./deploy.sh` returns a compilation error from the remote server, read the terminal output, identify the breaking Java/Kotlin/XML code, self-correct the code locally, and run `./deploy.sh` again until it succeeds.
